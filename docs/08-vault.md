# Зашифрованный сейф

Сервер хранит только шифротекст. Ключи появляются и используются только на устройствах взрослых членов семьи. Код: `FamilyCore/Sources/FamilyCore/Vault`, `ios/FamilyApp/Features/Vault`, миграция `20261003000200_vault.sql`.

## Схема ключей

| Ключ | Где хранится | Зачем |
|---|---|---|
| Identity (X25519) | приватная часть только в Keychain устройства (`WhenPasscodeSetThisDeviceOnly`, без iCloud); публичная на сервере | получать ключи сейфа |
| Резервная копия identity | на сервере, зашифрована ключом восстановления (160 бит, Crockford base32, HKDF) | новый телефон |
| Семейный ключ | на сервере по одной обёртке на каждого держателя (ECIES: эфемерный X25519 + HKDF + AES-256-GCM) | общие документы |
| Личный ключ | одна обёртка, для автора | документы «только я» |
| Ключ документа | случайный, обёрнут ключом сейфа (AAD: id документа и id ключа) | один файл |

Файл шифруется AES-256-GCM ключом документа, название и тип шифруются отдельно. В Storage (`vault`, приватный бакет) лежит `<family_id>/<item_id>`. Контекст каждой обёртки включает id ключа и получателя, поэтому её нельзя подсунуть в другое место.

## Как это работает
- **Первый запуск:** создаётся identity, показывается ключ восстановления (один раз; продолжить можно только после повторного ввода), затем создаются личный и семейный ключи.
- **Второй взрослый** публикует свой публичный ключ. Первый видит его в списке «Ждут доступа» вместе с **кодом безопасности** (30 цифр из обоих ключей), сверяет лично или по телефону и нажимает «Открыть доступ».
- **Новый телефон:** вводится ключ восстановления, identity расшифровывается из резервной копии.
- **Выход участника:** триггер в БД удаляет его обёртки и помечает семейный ключ `rotation_needed`. Админ нажимает «Обновить семейный ключ»: создаётся новый ключ, обёрнутый для оставшихся, ключи документов перешифровываются, сами файлы не трогаются. Сервер проверяет, что перешифрованы все документы.
- **Вход в раздел:** каждый раз Face ID / код-пароль; при закрытии экрана ключи стираются из памяти.

## Что проверено
- 47 pgTAP-проверок: изоляция семей, личные ключи, дети и гости без доступа, удалённый участник, ротация, Storage-политики, отсутствие прав на запись в служебные поля.
- 11 тестов криптографии: round-trip, подмена контекста и AAD, чужой ключ, неверный ключ восстановления, безопасные числа совпадают.
- 8 тестов модели: сервер не видит открытый текст и названия, восстановление на «новом устройстве», выдача доступа, личные документы скрыты, ротация после удаления, лимит размера.
- UI-сценарий: создание сейфа с подтверждением ключа восстановления.

## Ограничения (честно)
1. **Подмена публичного ключа сервером.** Если сервер подставит чужой публичный ключ второму взрослому, первый, не сверив код безопасности, откроет доступ чужому. Защита: сверка кода при выдаче доступа.
2. **Потеря ключа восстановления вместе с телефоном = потеря документов.** Расшифровать их не сможет никто. Пока второй взрослый держит семейный ключ, семейные документы доступны ему; личные нет.
3. **Удалённый участник** мог сохранить старый ключ и копии шифротекста, которые скачал раньше. Ротация защищает только новые документы и будущие загрузки.
4. **Просмотр документа** на время превью пишет расшифрованный файл во временную папку (`completeFileProtection`) и удаляет после закрытия и при выходе из раздела. При падении приложения файл может остаться до следующего открытия сейфа.
5. Если приложение закрыли между показом ключа восстановления и подтверждением, ключ повторно показать нельзя (identity уже опубликована). Нужна функция «выпустить новый ключ восстановления» (в планах).
6. Понижение или возврат участника стирает его личный ключ в этой семье (обёртка удалена), личные документы становятся нечитаемыми.
7. Размер файла до 20 МБ; все файлы читаются в память целиком.
8. Не проверено на реальном Supabase и на устройстве: Keychain, Face ID, QuickLook, загрузка в Storage.
